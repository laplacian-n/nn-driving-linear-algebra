# แผนการทดลอง (Experiment Protocol)

โครงงาน: 2D map self driving car neural network
สถานะเอกสาร: ฉบับอ้างอิง v1 (2026-10-16) ค่าที่มีเครื่องหมาย † จะยืนยันหลังการทดลองนำร่อง (ขั้น 0)

---

## 1. คำถามวิจัย

**คำถามหลัก:** รถต้องรับรู้สภาพแวดล้อมมากเพียงใด และต้องมีโครงข่ายประสาทขนาดใหญ่เพียงใด จึงจะขับรถในสนามแบบ F1 ได้ดี และโมเดลที่เรียนรู้แล้วบีบอัดให้เล็กลงได้มากเพียงใดโดยไม่เสียความสามารถ

| รหัส | คำถามย่อย | ขั้นที่ตอบ |
|---|---|---|
| RQ1 | ต้องใช้รังสีเซนเซอร์อย่างน้อยกี่เส้น และเพิ่มเซนเซอร์แล้วผลดีขึ้นแบบลดหลั่นหรือไม่ เมื่อขนาดโมเดลเท่ากัน | 1 |
| RQ2 | การลดมิติข้อมูลเซนเซอร์ด้วย PCA (eigenvector) ช่วยหรือทำให้เสียความสามารถ เมื่อขนาดโมเดลเท่ากัน | 2 |
| RQ3 | ความลึกและความกว้างของโครงข่ายส่งผลต่อความเร็วในการเรียนรู้และความสามารถสูงสุดอย่างไร และเมทริกซ์ตัวเดียว (ไม่มีชั้นซ่อน) ขับรถได้หรือไม่ | 3 |
| RQ4 | การบีบอัดแบบตัดโหนด (pruning) กับแบบลดบิต (quantization) แบบไหนเสียความสามารถน้อยกว่าที่ขนาดเท่ากัน | 4 |
| RQ5 | โมเดลใหญ่ที่ถูกบีบอัดจนเหลือขนาดเท่าโมเดลเล็ก เก่งกว่าโมเดลเล็กที่เทรนมาตั้งแต่ต้นหรือไม่ | 4 |
| RQ6 (เสริม) | โมเดลที่เทรนนานกว่า บีบอัดได้ดีกว่าโมเดลที่เทรนน้อยหรือไม่ | 4 |

## 2. นิยามศัพท์

| คำ | ความหมาย |
|---|---|
| config | ชุดค่าตัวแปรต้นหนึ่งชุด เช่น "เซนเซอร์ 9 เส้น, ไม่ใช้ PCA, 2×18" |
| run | การเทรน 1 config ด้วย seed 1 ค่า ตั้งแต่ต้นจนจบ |
| seed | ค่าเริ่มต้นของตัวสุ่มของ GA (น้ำหนักเริ่มต้น การกลายพันธุ์) ใช้ชุด {0, 1, 2} ทุก config |
| รุ่น (generation) | การประเมินประชากร 100 คันบนสนาม 1 ครั้ง แล้วสร้างประชากรใหม่ |
| snapshot | บันทึกประชากรทั้งชุด ทุก 25 รุ่น |
| champion | ตัวที่ได้คะแนน validation สูงสุดในบรรดา elite 8 ตัวของ snapshot นั้น |
| สนาม train | สนามที่ใช้เทรนตาม curriculum (seed ของสนาม 0, 1, 2, ...) |
| สนาม validation | 10 สนาม (seed 10000–10009) ความยาก 1.0 ใช้เลือก champion และเลือก config ที่ดีที่สุด |
| สนาม test | 20 สนาม (seed 20000–20019) ความยาก 1.0 ใช้รายงานผลเท่านั้น ห้ามใช้ตัดสินใจ |
| d | มิติ input ของโครงข่าย = จำนวนค่าเซนเซอร์ (หรือ k) + 4 ค่าสถานะรถ |
| D × w | โครงข่ายที่มีชั้นซ่อน D ชั้น ชั้นละ w โหนด (ทุกชั้นกว้างเท่ากัน) |
| P | จำนวนพารามิเตอร์ (น้ำหนัก + ไบแอส) |

จำนวนพารามิเตอร์ของ D × w ที่มี input d และ output 4:
`P = (d+1)·w + (D−1)·(w+1)·w + (w+1)·4` และกรณี Linear (D = 0): `P = (d+1)·4`

## 3. ตัวแปรควบคุมร่วม (ทุกขั้น)

### 3.1 ฟิสิกส์ของรถ (F1, เหมือนกันทุกการทดลอง)

| หัวข้อ | ค่า |
|---|---|
| แบบจำลอง | dynamic bicycle model 3 องศาอิสระ (vx, vy, yaw rate) + มุมเลี้ยวล้อ |
| มวล / โมเมนต์ความเฉื่อย | 798 kg / 1,200 kg·m² |
| ฐานล้อ / CG ถึงล้อหน้า, หลัง / ความสูง CG | 3.6 m / 1.95, 1.65 m / 0.30 m |
| ขนาดตัวรถ | 5.6 × 2.0 m |
| ยาง | Pacejka magic formula (B = 10, C = 1.9, E = 0.97), μ = 1.6 † มีจุดยึดเกาะสูงสุดแล้วตกลง จึงเกิดอาการท้ายสะบัดได้ |
| Friction circle | แรงตามยาวที่ใช้ไปลดแรงด้านข้างที่เหลือ: Fy,max = √((μFz)² − Fx²) |
| Load transfer | ตามยาว: ΔFz = m·ax·h / L (เบรกแล้วหน้าหนัก ท้ายเบา) |
| อากาศพลศาสตร์ | drag ½ρ·CdA·v² (CdA = 1.3), downforce ½ρ·ClA·v² (ClA = 4.2) แบ่งหน้า 45% |
| เครื่องยนต์ | กำลังสูงสุด 760 kW ขับล้อหลัง ถูกจำกัดด้วยแรงยึดเกาะล้อหลัง (ล้อฟรีได้) |
| เบรก | กระจายหน้า 60% / หลัง 40% แรงสูงสุดถูกจำกัดด้วยแรงยึดเกาะ |
| แฮนด์เบรก | ล็อกล้อหลัง: ล้อหลังเหลือแรงเสียดทานไถล ทำให้ท้ายหลุด |
| พวงมาลัย | มุมล้อสูงสุด ±0.35 rad อัตราหมุนจำกัด † |
| ความถี่ | ตัดสินใจ 30 ครั้ง/วินาที ฟิสิกส์ 240 ครั้ง/วินาที (8 substep) |
| ความเร็วสูงสุดตามทฤษฎี | ประมาณ 98 m/s (≈ 350 km/h) จากสมดุลกำลังกับ drag |

### 3.4 Genetic Algorithm และ fitness

| หัวข้อ | ค่า |
|---|---|
| ประชากร | 100 |
| elite / refine / immigrant | 8 / 20 / 8 ที่เหลือ 64 มาจากการผสมพันธุ์ |
| การเลือกพ่อแม่ | tournament k = 3 |
| crossover | สลับทั้งชั้น |

## 4. โปรโตคอลการประเมินผล

1. **ประเมิน champion:** ทุก snapshot นำ elite 8 ตัวขับสนาม validation ทั้ง 10 สนาม เลือกตัวที่ได้คะแนน validation สูงสุดเป็น champion แล้วให้ champion ขับสนาม test ทั้ง 20 สนาม
2. **ตัวชี้วัดต่อสนาม:** ร้อยละของรอบที่ไปได้ (progress, 0–100), จบรอบหรือไม่, เวลาต่อรอบ
3. **ตัวชี้วัดหลัก (คะแนน):** ค่าเฉลี่ย progress บนชุดสนาม (validation หรือ test)
4. **ตัวชี้วัดรอง:**
   - อัตราจบรอบ
   - ความเร็วเฉลี่ยบนสนามที่จบรอบ
   - **รุ่นแรกที่จบรอบ validation ได้ ≥ 50%** (ความเร็วในการเรียนรู้)
   - **AULC** คือพื้นที่ใต้กราฟคะแนน validation ตามรุ่น หารด้วยจำนวนรุ่น
5. **สถิติ:** รายงาน mean ± SE จาก 3 seed
6. **กฎเลือก config ที่ดีที่สุด (ใช้ validation เท่านั้น):**
   1. หา config ที่คะแนนเฉลี่ยสูงสุด
   2. config ทุกตัวที่คะแนนอยู่ภายใน 1 SE ของตัวสูงสุด ถือว่าเทียบเท่า
   3. ในกลุ่มที่เทียบเท่า เลือกตัวที่ **ง่ายที่สุด** (เซนเซอร์น้อยกว่า, k น้อยกว่า)
   4. ถ้ายังเสมอ เลือกตัวที่ความเร็วเฉลี่ยสูงกว่า
7. **นิยามอิ่มตัว:** หลังจากถึงความยาก 1.0 แล้ว ถ้าคะแนน validation ของ champion ไม่ดีขึ้นเกิน 0.5 จุด ในการวัด 4 ครั้งติด (100 รุ่น) ถือว่าอิ่มตัว และมีเพดาน 1,500 รุ่น †

## 5. ลำดับการทดลอง

```
ขั้น 0  Pilot          ยืนยันฟิสิกส์ + เรียนรู้ได้จริง + วัดเวลา
   │
ขั้น 1  เซนเซอร์       สมองชั่วคราว 2×16 (param-matched)         ──► ได้ S*
   │
ขั้น 2  PCA            S* เซนเซอร์ (param-matched)               ──► ได้ k* (หรือ "ไม่ใช้ PCA")
   │
ขั้น 3  ขนาดสมอง       S*, k*  กริด D×w 13 แบบ เทรนจนอิ่มตัว     ──► โมเดลทุกขนาด ทุกช่วงการเทรน
   │
ขั้น 4  บีบอัด          ประเมินผลอย่างเดียว ไม่เทรนเพิ่ม
```

แต่ละขั้นต้องรอขั้นก่อนหน้าเสร็จ เพราะใช้ค่าที่ดีที่สุดของขั้นก่อนเป็นตัวแปรควบคุม ภายในขั้นเดียวกันรันทุก run ขนานกัน (ประมาณ 10 run พร้อมกันบน 12 คอร์)

**สมองชั่วคราวของขั้น 1–2:** 2 ชั้นซ่อน (กลางกริดของขั้น 3) ขนาดพารามิเตอร์อ้างอิง P₀ = 692 คือ 2×16 ที่ input 21 มิติ (เซนเซอร์ 17 + สถานะ 4) เลือกค่านี้เพราะอยู่กลางกริด ไม่ได้เลือกให้เข้าข้างผลใด

## 6. รายละเอียดแต่ละขั้น

### ขั้น 0: Pilot

- **วัตถุประสงค์:**
  - ตรวจว่าฟิสิกส์ใหม่ทำงานถูก
  - ตรวจว่าประชากรเรียนรู้ได้จริงจนถึงความยาก 1.0
  - วัดเวลาต่อรุ่น
  - ยืนยันค่า †
- **การทดสอบฟิสิกส์ (ก่อนเทรน):** ขับด้วยตัวควบคุมสคริปต์แล้วเทียบกับค่าที่ควรเป็นของ F1

  | การทดสอบ | ค่าคาดหวัง |
  |---|---|
  | ความเร็วสูงสุดทางตรง | ≈ 95–98 m/s |
  | 0–100 km/h | ≈ 2.5–3.5 s |
  | เบรกจาก 300 km/h | ≈ 4.5–6 g |
  | แรงเข้าโค้งสูงสุดที่ 250 km/h | ≈ 4–5 g |
  | หักพวงมาลัยแรงที่ความเร็วสูง | ท้ายสะบัด / หมุน |
  | ดึงแฮนด์เบรกในโค้ง | ท้ายหลุด มุมลื่นไถลเพิ่ม |

- **การเทรน:** 2×16 กับเซนเซอร์ 17 เส้น seed 0 จำนวน 300 รุ่น
- **เกณฑ์ผ่าน:**
  - curriculum ถึงความยาก 1.0
  - champion จบรอบ validation ได้อย่างน้อย 1 สนาม
- **ถ้าไม่ผ่าน:** ปรับพารามิเตอร์ curriculum หรือ GA (ไม่ปรับฟิสิกส์ให้ง่ายลง) แล้วรันซ้ำ บันทึกการปรับไว้ในรายงาน
- **ผลลัพธ์:** งบรุ่นของขั้น 1–2 (G) และเวลาต่อรุ่นจริง

### ขั้น 1: จำนวนเซนเซอร์ (RQ1)

- **ตัวแปรต้น:** จำนวนรังสี S ∈ {3, 5, 9, 17}
  - ใช้ 2ⁿ+1 เพื่อให้ชุดรังสีซ้อนกันพอดี (3 ⊂ 5 ⊂ 9 ⊂ 17) แต่ละระดับละเอียดเชิงมุมขึ้นสองเท่า และมีรังสีตรงหน้าเสมอ
- **ตัวแปรตาม:** คะแนน validation/test ที่รุ่น G, AULC, รุ่นแรกที่จบรอบ ≥ 50%, ความเร็วเฉลี่ย
- **ตัวแปรควบคุมเฉพาะ:**
  - ไม่ใช้ PCA (ค่าดิบ) เพื่อให้เปลี่ยนแค่ปริมาณข้อมูล
  - มุมมองรวม 200° คงที่
  - **จำนวนพารามิเตอร์ล็อกไว้ที่ P₀ ± 4%** โดยปรับความกว้างชั้นซ่อน
- **ทำไมต้อง param-matched:** ถ้าใช้โครงข่ายเดียวกัน เซนเซอร์มากขึ้นจะทำให้ชั้นแรกมีน้ำหนักมากขึ้น ผลที่ดีขึ้นจะแยกไม่ออกว่าเพราะข้อมูลมากขึ้นหรือโมเดลใหญ่ขึ้น การล็อก P ทำให้ขนาดปริภูมิค้นหาของ GA และความจุเท่ากัน

| config | S | d | โครงข่าย | P | ต่างจาก P₀ |
|---|---|---|---|---|---|
| 1-S3 | 3 | 7 | 2×21 | 718 | +3.8% |
| 1-S5 | 5 | 9 | 2×20 | 704 | +1.7% |
| 1-S9 | 9 | 13 | 2×18 | 670 | −3.2% |
| 1-S17 | 17 | 21 | 2×16 | 692 | 0% |

- **จำนวนรัน:** 4 config × 3 seed = 12 run
- **ผลที่คาดหวัง:**
  - S = 3 ด้อยชัดเจน: มองไม่เห็นว่าโค้งข้างหน้าเลี้ยวไปทางไหนจนสายเกิน เพราะมีแค่รังสีตรงและสองข้าง จะชนในโค้งต่อเนื่องและ hairpin บ่อย
  - คะแนนเพิ่มชัดจาก 3 → 5 → 9 แล้วเริ่มอิ่มที่ 9 → 17 (diminishing returns) เพราะรังสีที่ชิดกันให้ข้อมูลซ้ำกันมาก ซึ่งขั้น 2 จะวัดตรงนี้ด้วย PCA
  - S = 17 อาจเรียนช้ากว่า 9 เล็กน้อย (AULC ต่ำกว่า) เพราะชั้นแรกมีน้ำหนักมากขึ้น ชั้นซ่อนจึงต้องแคบลงเพื่อรักษา P
  - คาดว่า S* = 9 (ตามกฎ 1 SE)
- **กราฟ/ตาราง:**
  - กราฟการเรียนรู้ (คะแนน validation ตามรุ่น, mean ± SE)
  - กราฟแท่งคะแนน test
  - กราฟคะแนนเทียบ S (แกน log2)
- **ส่งต่อ:** S* ไปขั้น 2

### ขั้น 2: การลดมิติด้วย PCA (RQ2)

- **ตัวแปรต้น:** k ∈ {2, 4, 8} (เฉพาะค่าที่ < S*) เทียบกับไม่ใช้ PCA (ใช้ผลของ 1-S* จากขั้น 1 ได้เลย ไม่ต้องรันซ้ำ)
- **ตัวแปรควบคุมเฉพาะ:** เซนเซอร์ S* เส้น, จำนวนพารามิเตอร์ล็อกที่ P₀ ± 4%
- **ตัวอย่างกรณี S* = 9 หรือ 17:**

| config | k | d | โครงข่าย | P |
|---|---|---|---|---|
| 2-K2 | 2 | 6 | 2×21 | 697 |
| 2-K4 | 4 | 8 | 2×20 | 684 |
| 2-K8 | 8 | 12 | 2×19 | 707 |

  ถ้า S* = 5 ใช้ k ∈ {2, 4}, ถ้า S* = 3 ข้ามขั้นนี้ (k* = ไม่ใช้ PCA)
- **จำนวนรัน:** ≤ 3 config × 3 seed = 9 run
- **การวิเคราะห์เชิงพีชคณิตเชิงเส้น (ไม่ต้องเทรน):**
  - scree plot: eigenvalue และร้อยละความแปรปรวนสะสม
  - วาด eigenvector 4 ตัวแรกเป็นรูปพัดเซนเซอร์ (ค่าของแต่ละรังสี) เพื่อตีความ
- **ผลที่คาดหวัง:**
  - eigenvalue ลดลงเร็ว: 4–8 องค์ประกอบแรกอธิบายความแปรปรวนได้ ≥ 90% เพราะระยะของรังสีข้างเคียงสัมพันธ์กันสูง
  - eigenvector ตีความได้: PC1 ≈ "ข้างหน้าโล่งแค่ไหน" (ทุกรังสีบวกพร้อมกัน), PC2 ≈ "ซ้ายต่างขวา" (สัญญาณบอกทิศโค้ง), PC3 ≈ "ตรงกลางต่างด้านข้าง"
  - k = 2 ด้อยลง เพราะเสียรายละเอียดเชิงมุมที่จำเป็นในโค้งต่อเนื่อง
  - k = 4–8 ได้ผลเทียบเท่าค่าดิบ และเรียนเร็วกว่า เพราะ input ไม่ซ้ำซ้อน ชั้นซ่อนจึงกว้างขึ้นได้ภายใต้ P เท่าเดิม
  - คาดว่า k* = 4 หรือ 8
- **กราฟ/ตาราง:** scree plot, รูป eigen-sensor, กราฟการเรียนรู้, กราฟแท่ง test
- **ส่งต่อ:** k* ไปขั้น 3

### ขั้น 3: ขนาดสมอง (RQ3)

- **ตัวแปรต้น:** 2 ปัจจัยแบบ factorial (ทุกชั้นซ่อนกว้างเท่ากัน)
  - ความลึก D ∈ {1, 2, 3}
  - ความกว้าง w ∈ {4, 8, 16, 32} (เพิ่มทีละสองเท่า)
  - บวก Linear (D = 0, เมทริกซ์ตัวเดียว + tanh) รวม 13 โครงสร้าง
- **ตัวแปรควบคุมเฉพาะ:** S*, k* จากขั้น 1–2 (**ไม่** ล็อก P เพราะขนาดคือสิ่งที่ศึกษา)
- **จำนวนพารามิเตอร์** (ตัวอย่างเมื่อ d = 12 คือ k* = 8):

| D \ w | 4 | 8 | 16 | 32 |
|---|---|---|---|---|
| 0 (Linear) | 52 | | | |
| 1 | 72 | 140 | 276 | 548 |
| 2 | 92 | 212 | 548 | 1,604 |
| 3 | 112 | 284 | 820 | 2,660 |

  ขนาดครอบคลุมราว 50 เท่า ข้อสังเกต: 1×32 กับ 2×16 มี P = 548 เท่ากันพอดี ใช้แยกผลของ "รูปทรง" ออกจาก "จำนวนพารามิเตอร์" ได้โดยตรง
- **การเทรน:** แต่ละ run เทรนจนอิ่มตัว (ข้อ 4.7) เก็บ snapshot ทุก 25 รุ่น จากรันเดียวได้ข้อมูลสองแบบ
  - **แบบงบเท่ากัน:** อ่านผลที่รุ่น G จาก snapshot เทียบความเร็วในการเรียนรู้
  - **แบบอิ่มตัว:** ผลของ snapshot สุดท้าย คือความสามารถสูงสุด
- **จำนวนรัน:** 13 × 3 seed = 39 run
- **การวิเคราะห์เชิงพีชคณิตเชิงเส้น:** SVD ของเมทริกซ์น้ำหนักแต่ละชั้นของโมเดลอิ่มตัว
  - singular value spectrum
  - effective rank = จำนวน singular value ที่รวมพลังงาน (Σσ²) ได้ 90%
- **ผลที่คาดหวัง:**
  - **Linear:** ขับได้บางส่วนบนสนามง่าย (นโยบาย "เลี้ยวตามความต่างซ้าย-ขวา" เป็นฟังก์ชันเกือบเชิงเส้น) แต่จบรอบที่ความยาก 1.0 ได้น้อย เพราะการตัดสินใจเบรกก่อนโค้งเป็นฟังก์ชันไม่เชิงเส้นของระยะและความเร็ว
  - **งบเท่ากัน:** โมเดลขนาดกลาง (2×8, 1×16, 2×16) เรียนเร็วที่สุด ส่วน w = 32 และ D = 3 เรียนช้ากว่า เพราะ GA ค้นหาในปริภูมิมิติสูงได้ช้ากว่า (การกลายพันธุ์แบบสุ่มมีโอกาสไปทางที่ดีน้อยลงเมื่อมิติมาก)
  - **อิ่มตัว:** ความต่างแคบลง โมเดลใหญ่ไล่ทันและอาจมีเพดานสูงกว่าเล็กน้อย ส่วน w = 4 มีเพดานต่ำชัดเจน (คอขวดข้อมูล)
  - **ความลึก vs ความกว้าง:** ที่ P เท่ากัน (1×32 vs 2×16) คาดว่าลึกกว่าได้เปรียบเล็กน้อยในงานที่ต้องผสมหลายเงื่อนไข (ความเร็ว × ระยะ × ทิศ)
  - **SVD:** โมเดลกว้าง (w = 32) มี effective rank ต่ำกว่าความกว้างมาก แปลว่าใช้มิติจริงไม่เต็ม เป็นหลักฐานว่าตัดโหนดได้โดยเสียผลน้อย (เชื่อมกับขั้น 4)
- **กราฟ/ตาราง:**
  - heatmap คะแนน (D × w) สองภาพ: งบเท่ากัน และอิ่มตัว
  - กราฟคะแนนเทียบ P (แกน log)
  - กราฟการเรียนรู้แยกตามความลึก
  - singular value spectrum ต่อชั้น
- **ส่งต่อ:** snapshot ทุกโมเดลทุกช่วงการเทรนไปขั้น 4

### ขั้น 4: การบีบอัดโมเดล (RQ4, RQ5, RQ6)

ทุกการทดลองย่อยเป็นการประเมินผลอย่างเดียว ไม่เทรนซ้ำ (post-training compression) วัดด้วยสนาม test โปรโตคอลเดิม

**ขนาดโมเดล (บิต):**
- ขนาด = P × จำนวนบิตต่อพารามิเตอร์ + 32 บิตต่อชั้นสำหรับค่าสเกล (กรณี quantize)
- โมเดลที่ไม่บีบอัดนับ 32 บิตต่อพารามิเตอร์ (float32)

**นิยามวิธีบีบอัด**
- **Pruning ตามความทำงาน:**
  1. ให้โมเดลขับสนาม validation แล้วเก็บค่า activation ของทุกโหนดในชั้นซ่อน
  2. คะแนนความทำงานของโหนด = ส่วนเบี่ยงเบนมาตรฐานของ activation
  3. ตัดโหนดคะแนนต่ำสุดออก (ลบแถวของ W ชั้นนั้น และลบคอลัมน์ของ W ชั้นถัดไป)
  4. ชดเชยด้วย b_ถัดไป ← b_ถัดไป + W_ถัดไป[:, ตัด] · ค่าเฉลี่ย activation[ตัด] ซึ่งเป็นการประมาณเชิงเส้นว่าโหนดที่แทบไม่เปลี่ยนค่าเทียบเท่าค่าคงที่
- **Pruning แบบสุ่ม (กลุ่มควบคุม):** ตัดโหนดแบบสุ่มด้วยการชดเชยเดียวกัน ทำซ้ำ 5 ครั้งแล้วเฉลี่ย
- **Quantization:** ต่อชั้น แบบสมมาตรสม่ำเสมอ
  - สเกล s = max|W| / (2^(b−1) − 1)
  - W_q = s · round(W / s) ใช้กับทั้ง W และ b
- **ผสม (prune แล้ว quantize):** ใช้เมื่อเป้าหมายเล็กเกินกว่าที่ quantization อย่างเดียวทำได้

#### 4.1 กราฟการเสื่อมพื้นฐาน (RQ4)
- **ตัวแปรต้น:**
  - วิธี: prune ตามความทำงาน / prune สุ่ม / quantize
  - ระดับ prune: ตัดโหนดออก 0, 25, 50, 75, 90% ทุกชั้นเท่ากัน
  - ระดับ quantize: 16, 8, 6, 4, 3, 2 บิต
- **ใช้กับ:** โมเดลอิ่มตัว w = 32 ทุกความลึก (D = 1, 2, 3) × 3 seed
- **ผลที่คาดหวัง:**
  - quantize 16 และ 8 บิต แทบไม่เสียผล (< 1 จุด)
  - 6 บิตเริ่มเสียเล็กน้อย
  - 3–2 บิตพังเร็ว เพราะการตัดสินใจเบรกขึ้นกับความต่างเล็ก ๆ ของ input
  - prune ตามความทำงานทนได้ถึง ~50% ซึ่งสัมพันธ์กับ effective rank ของขั้น 3
  - prune สุ่มพังเร็วกว่าชัดเจน ยืนยันว่าเกณฑ์ความทำงานมีความหมาย
  - โครงข่ายลึก (D = 3) ไวต่อ quantize มากกว่า เพราะความคลาดเคลื่อนสะสมผ่านหลายชั้น

#### 4.2 Pruning ให้ได้รูปทรงเดียวกับโมเดลเล็ก (RQ5 ข้อเปรียบเทียบหลัก)
- **วิธี:** ตัดความกว้างลงทีละครึ่งในความลึกเดิม ผลลัพธ์มี **รูปทรงตรงกับโมเดลในกริดของขั้น 3 ทุกประการ** จึงมี P เท่ากันพอดี

| ต้นทาง (อิ่มตัว) | บีบ 1 ระดับ | บีบ 2 ระดับ | บีบ 3 ระดับ |
|---|---|---|---|
| D×32 | → D×16 | → D×8 | → D×4 |
| D×16 | → D×8 | → D×4 | |
| D×8 | → D×4 | | |

- **เปรียบเทียบ:** "D×32 ที่ prune เหลือ D×8" กับ "D×8 ที่เทรนเองจนอิ่มตัว" ขนาดเท่ากันทุกบิต
- **ผลที่คาดหวัง:**
  - บีบ 1 ระดับ: โมเดลใหญ่ที่บีบ **ดีกว่าหรือเท่า** โมเดลเล็กที่เทรนเอง เพราะโมเดลใหญ่หาวิธีขับที่ดีกว่าได้ก่อน แล้วความรู้ส่วนใหญ่อยู่ในโหนดที่ทำงานมาก
  - บีบ 2–3 ระดับ: โมเดลเล็กที่เทรนเอง **ชนะ** เพราะโมเดลใหญ่ไม่ได้ถูกฝึกให้ทำงานด้วยโหนดน้อย การตัด 75–87% โดยไม่เทรนซ้ำทำลายการประสานงานระหว่างโหนด
  - จุดตัดของสองเส้นนี้ คือคำตอบเชิงปริมาณของ RQ5

#### 4.3 Quantization ให้ได้ขนาดเท่าโมเดลเล็ก (RQ5)
- **วิธี:** เลือกจำนวนบิต b = 32 · P_เล็ก / P_ใหญ่ (ปัดลงเป็นจำนวนเต็ม) ให้ขนาดรวมไม่เกินโมเดลเล็กเป้าหมาย
- **ตัวอย่าง (d = 12):** จำนวนบิตที่ต้องใช้ ถ้าต้นทางเป็น D×32

| เป้าหมาย | D = 1 | D = 2 | D = 3 |
|---|---|---|---|
| ขนาดเท่า D×16 | 16 บิต | 10 บิต | 9 บิต |
| ขนาดเท่า D×8 | 8 บิต | 4 บิต | 3 บิต |
| ขนาดเท่า D×4 | 4 บิต | **1.8 → ทำไม่ได้** | **1.3 → ทำไม่ได้** |

- **ข้อสังเกตสำคัญ:**
  - quantization อย่างเดียวบีบได้สูงสุดประมาณ 16 เท่า (32 → 2 บิต)
  - ส่วน pruning ลด P ได้ตามกำลังสองของความกว้าง (w → w/2 ลดน้ำหนักชั้นกลางประมาณ 4 เท่า)
  - เป้าหมายที่เล็กมากจึงต้องใช้แบบผสม (ข้อ 4.4) **นี่คือเหตุผลเชิงโครงสร้างที่ทำให้สองวิธีไม่ได้เท่ากันโดยธรรมชาติ**
- **ผลที่คาดหวัง:**
  - ที่ขนาดเท่า D×16 (บีบ ~3 เท่า): quantize ชนะ prune และชนะโมเดลเล็ก เพราะ 9–16 บิตแทบไม่เสียผล
  - ที่ขนาดเท่า D×8 (บีบ ~7.5 เท่า): quantize 3–4 บิตเริ่มเสีย ผลอาจใกล้เคียงหรือแพ้โมเดลเล็ก

#### 4.4 แบบผสม: prune แล้ว quantize
- **วิธี:** สำหรับแต่ละเป้าหมายขนาด ลองทุกคู่ (ระดับ prune, จำนวนบิต) ที่ขนาดรวมไม่เกินเป้า แล้วเลือกคู่ที่ดีที่สุดด้วย **validation** ก่อนรายงานผล **test**
- **ผลที่คาดหวัง:** ที่การบีบสูง แบบผสม (prune พอประมาณ + 6–8 บิต) ดีกว่าการใช้วิธีเดียวแบบสุดขั้ว

#### 4.5 Pareto: ผลเทียบขนาด (สรุป RQ4 + RQ5)
- **จุดบนกราฟ:**
  - โมเดลอิ่มตัวทุกขนาดในกริด
  - ทุกผลจาก 4.1–4.4
- **กราฟ:** คะแนน test เทียบขนาด (บิต, แกน log) แยกสีตามกลุ่ม: เทรนเอง / prune / quantize / ผสม พร้อมเส้น Pareto
- **คำตอบที่ได้:** ที่ขนาดหนึ่ง ๆ วิธีไหนให้คะแนนสูงสุด และ "เทรนใหญ่แล้วบีบ" หรือ "เทรนเล็ก" ดีกว่าที่ระดับขนาดใด

#### 4.6 ความสามารถในการบีบอัด เทียบระยะเวลาเทรน (RQ6, เสริม)
- **วิธี:** ใช้ snapshot ของ 2×32 ที่รุ่น 100, 200, 400, ... จนอิ่มตัว บีบด้วยระดับคงที่ (prune 50%, quantize 4 บิต) แล้ววัด **การลดลงของคะแนน** (ก่อน − หลังบีบ)
- **ผลที่คาดหวัง:** โมเดลที่เทรนนานขึ้นทนการบีบอัดได้ดีขึ้น เพราะ GA ที่มี elite และ refine ค่อย ๆ คัดตัวที่ทนต่อการรบกวนของน้ำหนักไว้ (การกลายพันธุ์คือการรบกวนน้ำหนักแบบหนึ่ง) แต่ผลอาจกลับทางสำหรับ pruning ถ้าโมเดลเทรนนานกระจายงานไปทุกโหนด
