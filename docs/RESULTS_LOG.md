ครู = ตัวควบคุมอ้างอิง (pure pursuit + speed profile) ใช้ยาง x% ของขีดจำกัด; สะสมข้อมูลทุกสถานี ("all") ยกเว้นระบุ

| ชุด | XS | S | L | XL | เวลา/run |
|---|---|---|---|---|---|
| ครู 85%, ข้อมูลเฉพาะสถานี (`bc`) | 4 | 18 | 5 | 16 | ~10 นาที |
| ครู 85% (`bc_all`) | 9 | 30 | 54 | 59 | ~12 นาที |
| ครู 85%, เทรน 2 เท่า (`bc_long`) | 8 | 46 | 73 | 73 | ~65 นาที |
| **ครู 75%, เทรน 2 เท่า (`bc_t75_long`)** | 16 | 82 | 88 | **94** | ~60 นาที |
| ครู 65% (`bc_t65`) | 27 | 95 | 96 | 95 | ~60 นาที* |
| ครู 45% (`bc_t45`) | 84 | 99 | 98 | 100 | ~60 นาที* |

สนามยาก: `bc_long` 1 / 26 / 54 / 56, `bc_t75_long` **5 / 70 / 78 / 91**, `bc_t65` 9 / 91 / 96 / 93, `bc_t45` 67 / 99 / 96 / 100
ต่อ seed `bc_t75_long`: XS 17,13,20,14; S 80,90,84,79; L 89,87,90,85; XL 97,95,93,86
(*เวลาของชุดที่รัน 48 run พร้อมกันบน 12 core)

ข้อค้นพบ
1. ใช้ gradient แล้วโมเดลใหญ่ชนะ และชนะมากขึ้นเมื่องานต้องการความแม่น (ครูขับเร็ว) ครูช้ามาก → ceiling effect ทุกขนาด ≈ 100%
2. ข้อมูลเฉพาะสถานี → catastrophic forgetting (L 41 → 5); สะสมข้อมูล → แทบไม่ลืม
3. โมเดลใหญ่ต้องการเวลาเทรนมากกว่า (bc_all → bc_long: L 54 → 73, S 30 → 46)
4. Linear เลียนแบบครูไม่ได้ (การตัดสินใจของครูไม่เชิงเส้น) แต่ใน GA Linear ได้ 70 เพราะหาวิธีขับแบบง่ายเอง
   - หลักฐาน (notebook หัวข้อ 10): least squares (สมการปกติ) บนข้อมูลการขับ 18,235 แถว: R² เชิงเส้น พวงมาลัย 0.987 / คันเร่ง 0.334 / เบรก 0.091 เทียบกับ network 2×32: 0.977 / 0.516 / 0.476 → เลี้ยวเป็นเชิงเส้น แต่การคุมความเร็วไม่ใช่
5. ครูที่ขับใกล้ขีดจำกัดมีข้อมูลที่นักเรียนไม่มี (เส้นกลางถนน, ความโค้งล่วงหน้า) → "privileged expert"; ครูเร็ว 85% ขับ 32–43 m/s
6. BC ดีที่สุด (ครู 45–75%) > GA ทั้งอัตราจบรอบและความเร็ว (~25–32 m/s เทียบ ~20 m/s) โดยใช้เวลาน้อยกว่า ~10 เท่า

## ชุด D: จำนวนเซนเซอร์ / PCA (BC ครู 75 %, เทรน 2 เท่า, L 2×32, 4 seed, `experiments/results/sensors`)

| input เซนเซอร์ | มิติ | รวม 7 ระดับ | สนามยาก | ต่อ seed |

| รังสีดิบ 3 เส้น | 3 | 0 | 0 | 0,0,0,0 |
| รังสีดิบ 5 เส้น | 5 | 56 | 36 | 38,60,66,52 |
| รังสีดิบ 9 เส้น | 9 | 88 | 79 | 89,87,90,85 |
| รังสีดิบ 17 เส้น | 17 | 96 | 98 | 97,88,95,100 |

ข้อค้นพบ
1. รังสีมากขึ้นดีขึ้นชัด (3 → 17: 0 → 96) ข้อมูลรอบตัวสำคัญ

4. PCA 17 ≈ raw 17 (97 vs 96): การหมุนแกนด้วยเมทริกซ์ตั้งฉากไม่เปลี่ยนข้อมูล
5. PCA 2 ล้มเหลว (สอดคล้องกับ scree: 2 PC อธิบายความแปรปรวนได้ ~56 %)

## ชุด E: บีบอัดโมเดล BC (`stage4_bc`) + เพิ่ม low-rank SVD ทั้งสองชุด

| | GA: XL (61) | BC: XL (94) | BC: L (87) |
|---|---|---|---|
| quantise 8 bit | 57 | **92** | 81 |
| quantise 6 bit | — | 80 | 62 |
| prune → 32 LS | 45 | **1** | — |
| prune → 8 LS | 7 | 1 | 5 |
| low rank 16 / 8 / 4 / 2 (SVD) | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 | 88* / 0 / 0 / 0 |

(*rank 16 ของ 32×32 ไม่ได้ลดขนาดจึงไม่ได้ตัด) BC trained: S 82 (7 kbit), L 88 (52 kbit), XL 94 (170 kbit)

ข้อค้นพบ
1. BC: XL 8 bit (48 kbit, 92 %) **ดีกว่า L ที่เทรนเอง (52 kbit, 88 %) ทั้งที่เล็กกว่า** → กรณีโมเดลใหญ่เก่งจริง "ใหญ่แล้วบีบด้วยการลดบิต" ชนะ "เล็กแล้วเทรน" ที่ขนาดเท่ากัน
2. การตัดโหนดพังหมดในโมเดล BC (แม้ LS) ทั้งที่ใน GA LS ยังรอด 45 %: BC กระจายความรู้ไปทุกโหนด
3. effective rank (พลังงาน 90 %) ของ W ชั้นกลาง: BC ต่ำกว่า GA (XL: 26 vs 33 จาก 64; L: 13 vs 17 จาก 32) แต่ low-rank SVD ก็ยังพัง → การขับแบบวงปิดไวต่อความคลาดเคลื่อนเล็ก ๆ ที่สะสม (open-loop error เล็กแต่ closed-loop พัง)
4. ผลสอบซ้ำของโมเดลเดิมแกว่ง ±5 จุดตามสัญญาณรบกวนเซนเซอร์ (XL GA 8 bit: 62 รอบแรก, 57 รอบนี้)

## สิ่งที่ยังไม่ได้ทำ / กำลังทำ
- ยังไม่ได้: demo กับเพื่อน ≥ 10 ครั้ง, วิดีโอ, สไลด์, รายงาน
- ทางเลือกถ้าเวลาเหลือ (ผู้ทำโครงงานสนใจ, ตัดสินใจภายหลัง): **BC → GA** ให้ BC สอนพื้นฐานแล้วใช้โมเดล BC เป็นประชากรตั้งต้นของ GA ฝึกต่อเองด้วยรางวัล ในการทดลองขนาดโมเดล (ดูว่าเกินครูได้ไหม / ค้นพบวิธีขับเองไหม / ขนาดไหนได้ประโยชน์) ~3–5 ชม.
- กรอบเรื่องในรายงาน: GA (รถฝึกเองจากรางวัล) เป็นแกนหลักตามแนวคิดโครงงาน; BC + DAgger (เรียนจากครูที่เขียนกฎไว้ ซึ่งรู้แผนที่สนาม = privileged expert) เป็นการทดลองเปรียบเทียบ; ชุด D ใช้ BC เพราะข้อจำกัดด้านเวลา
