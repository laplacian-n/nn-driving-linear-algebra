### สไลด์ 2 — ที่มาของปัญหา (0:40)
- รถขับเองต้องตัดสินใจจากเซนเซอร์หลายมิติทุกเสี้ยววินาที และคุมพวงมาลัย คันเร่ง เบรกพร้อมกัน
- เขียนกฎให้ครอบคลุมทุกสถานการณ์ยาก โดยเฉพาะตอนเร็วจนยางใกล้หลุด
- คำถาม: neural network เล็กแค่ไหนก็ขับได้? ต้องใช้เซนเซอร์เท่าไร? ควรฝึกแบบไหน? บีบอัดได้แค่ไหน?

### สไลด์ 3 — ไอเดียและแนวทางที่เลือก (0:40)
- จำลองรถแข่ง 2D ฟิสิกส์สมจริง (ยาง Pacejka, แรงกดอากาศ, ท้ายปัด, แฮนด์เบรก) + สนาม F1 สุ่มใหม่ทุกครั้ง ความยาก 0–3
- รถรู้จักสนามผ่านรังสีวัดระยะ 9 เส้นเท่านั้น → neural network → 4 คำสั่ง
- ฝึก 2 แบบ: **Genetic Algorithm** (รถลองผิดลองถูกเอง) และ **เรียนจากครู** (behavior cloning + DAgger ด้วย gradient)
- ทุกอย่างเขียนเองด้วย NumPy — พีชคณิตเชิงเส้นอยู่ในทุกขั้น
รูป: `figures/tracks_d10.png` หรือ `figures/tracks_d30.png`

### สไลด์ 4 — ภาพรวมขั้นตอน (0:40)
ลำดับ: สร้างสนาม → ฟิสิกส์ → เซนเซอร์ (ระบบสมการ 2×2) → เวกเตอร์อินพุต 13 มิติ → neural network (คูณเมทริกซ์) → คำสั่ง → ฝึก (GA / gradient) ตามหลักสูตร 7 สถานี → สอบ 210 สนามที่ไม่เคยเห็น
- เตรียมข้อมูล: 22,819 แถว → สมบูรณ์ 77.8 % / แก้ไข 16.8 % / ตัดทิ้ง 5.4 % → PCA
รูป: `figures/data_row_quality.png`, `figures/data_pca_scree.png`

### สไลด์ 5 — พีชคณิตเชิงเส้นที่ใช้ (0:50)
| เวกเตอร์ | เมทริกซ์ |
|---|---|
| บวกเวกเตอร์ + หมุน: การเคลื่อนที่ | กฎของคราเมอร์: จุดตัดรังสีกับขอบถนน |
| ผลคูณจุด/การฉาย: ระยะบนสนาม, การชน | คูณเมทริกซ์แบบกลุ่ม: neural network 100 ตัวพร้อมกัน |
| ผลคูณไขว้: ความโค้งถนน | ค่าไอเกน: PCA ลด 17 → 4 มิติ |
| ปริภูมิน้ำหนัก: การกลายพันธุ์ GA | ทรานสโพส/ผลคูณภายนอก: backpropagation |
| | สมการปกติ: ตัดโหนด · SVD: low-rank |
รูป: `figures/data_eigen_sensors.png` (แกน PCA มีความหมาย: กว้าง/แคบ, ซ้าย/ขวา, หน้า/ข้าง)

### สไลด์ 6 — ผล 1: GA กับขนาดโมเดล (0:50)
- 4 ขนาด × 4 seed, ทุกสถานีฝึกจนอิ่มตัว: ระหว่างฝึกทุกขนาดได้ 74–78 % เท่ากัน
- หลังฝึก: **S 2×8 ดีสุด 81 %**, XL ลืมสนามง่าย (ระดับ 0.5: 90 → 58 %)
- ขัดสามัญสำนึก → ตรวจแล้วไม่ใช่เพราะเกณฑ์อิ่มตัว → สงสัยว่า GA หาทางในมิติสูงไม่ได้
รูป: `figures/s3_station_finish.png` (หรือ `s3_overall.png`)

### สไลด์ 7 — ผล 2: เปลี่ยนเป็นเรียนจากครูด้วย gradient (0:50)
- โมเดลใหญ่ชนะจริง: XS 16 → S 82 → L 88 → **XL 94 %** (สนามยาก 5 → 70 → 78 → 91 %)
- ยิ่งงานต้องแม่น (ครูขับเร็ว) โมเดลใหญ่ยิ่งได้เปรียบ; ครูช้าเกินไป → ทุกขนาดได้ ~100 %
- ครูที่ "โกง" (รู้แผนที่) แต่ขับใกล้ขีดจำกัด สอนไม่ได้ → ครูที่เผื่อระยะสอนดีกว่า
- ฝึกเร็วกว่า GA ~10 เท่า
รูป: `figures/cmp_variants_by_level.png`

### สไลด์ 8 — ผล 3: เซนเซอร์และ PCA (0:40)
- 3 รังสี 0 % · 9 รังสี 88 % · 17 รังสี 96 %
- **PCA 4 มิติจาก 17 รังสี = 93 %** > รังสีจริง 9 เส้น; ทิศสุ่ม 4 มิติได้แค่ 50 % → เวกเตอร์ไอเกนมีความหมาย
- PCA 17 มิติ = หมุนแกน = ผลเท่าเดิม
รูป: `figures/sens_dimensions.png`

### สไลด์ 9 — ผล 4: การบีบอัด (0:30)
- 8 bit: เล็กลง 3.6 เท่า แทบไม่เสีย (94 → 92 %) → XL 8 bit ดีกว่า L ที่ฝึกเองทั้งที่เล็กกว่า
- ตัดโหนด / low-rank SVD: พัง เพราะความคลาดเคลื่อนสะสมในการขับแบบวงปิด

### สไลด์ 12 — สรุปและปัญหาที่พบ (0:45)
- ขนาดโมเดลที่เหมาะขึ้นกับวิธีฝึก · การลืมแก้ด้วยการทบทวนข้อมูล · ครูที่ดีสำคัญกว่าขนาด · PCA ลดมิติได้มาก · 8 bit คือการบีบอัดที่ปลอดภัย
- ปัญหา: รถหมุนง่ายเกินจริง → ปรับยาง · เซนเซอร์ช้า → Numba 8× · โมเดลลืมถนนกว้าง → rehearsal · เวลาไม่พอ → ลดขนาดการทดลอง + BC · ตัดโหนดพัง → ใช้ 8 bit
- ต่อยอด: RL ด้วย gradient (PPO), จำลองบน GPU, seed มากขึ้น
