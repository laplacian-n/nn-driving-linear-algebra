## 1. คำถามวิจัยและเกณฑ์ตัดสิน

**คำถามหลัก:** นโยบายขับรถแบบโครงข่ายประสาทที่วิวัฒน์ด้วย GA ต้องใช้ข้อมูลการรับรู้และขนาดโครงข่ายเท่าใด จึงจะขับในสนามแบบ F1 (ย่อส่วน) ได้ดี และบีบอัดได้มากเพียงใดโดยไม่เสียความสามารถ

| รหัส | คำถาม | เกณฑ์ตัดสินที่กำหนดล่วงหน้า |
|---|---|---|
| RQ1 | จำนวนรังสีน้อยที่สุดที่ "เพียงพอ" คือเท่าใด เพิ่มแล้วผลดีขึ้นแบบลดหลั่นหรือไม่ | "เพียงพอ" = S น้อยที่สุดที่ **เทียบเท่า** (TOST, δ = 5 คะแนน) กับ S ที่ดีที่สุด, "ลดหลั่น" = Δ(5→9) − Δ(9→17) > 0 โดย 95% CI ไม่คร่อม 0 |
| RQ2 | PCA k มิติจากรังสี 17 เส้น ดีกว่ารังสีดิบที่มิติใกล้กันหรือไม่ และดีกว่าการฉายแบบสุ่มหรือไม่ | ผลต่างแบบจับคู่ K2↔S3, K4↔S5, K8↔S9 และ PCA↔Random projection ที่ k เดียวกัน พร้อม 95% CI |
| RQ3 | ความลึกและความกว้างมีผลต่อความเร็วในการเรียนและเพดานความสามารถอย่างไร | heatmap + ผลต่างที่กำหนดล่วงหน้า (ข้อ 6.3) ส่วน "Linear ขับได้" = อัตราจบรอบบน T ≥ 50% |
| RQ4 | ที่อัตราส่วนการบีบอัดเท่ากัน วิธีใดเสียคะแนนน้อยที่สุด | เส้นคะแนนเทียบ compression ratio ต่อวิธี เทียบที่ ratio ∈ {2, 4, 8, 16} |
| RQ5 | โมเดลใหญ่ที่บีบอัดให้ขนาดเท่าโมเดลเล็ก ดีกว่าโมเดลเล็กที่เทรนเองหรือไม่ | ผลต่างแบบจับคู่ที่ขนาดเท่ากัน ทั้งแบบไม่ fine-tune และ fine-tune, H5a หรือ H5b (ข้อ 6.4) |
| RQ6 (เสริม) | โมเดลที่เทรนนานกว่าบีบอัดได้ดีกว่าหรือไม่ และเพราะกลไกใด | ความชันของการเสียคะแนนเทียบเวลาเทรน หลังจับคู่ตามคะแนนฐาน พร้อมตัวแปรกลไก (ข้อ 6.4.6) |

## 2. นิยามศัพท์

| คำ | ความหมาย |
|---|---|
| config | ชุดค่าตัวแปรต้นหนึ่งชุด |
| run | การเทรน 1 config ด้วย 1 seed |
| seed | seed หลักของ run แตกเป็น RNG stream อิสระด้วย `numpy.random.SeedSequence`: (ก) GA (ข) ลำดับสนามฝึก (ค) noise ของเซนเซอร์ ใช้ seed {0, 1, 2, 3, 4} ทุก config |
| รุ่น | ประเมินประชากรทั้งหมดบนสนามฝึก 3 สนามแล้วสร้างประชากรใหม่ |
| ก้าว | หนึ่งการตัดสินใจ (1/30 วินาที) ถ้าเป็นฟิสิกส์จะเรียก "substep" (1/240 วินาที) |
| snapshot | ประชากรทั้งชุด บันทึกทุก 25 รุ่น |
| champion ของ snapshot | elite ที่ได้ race score สูงสุดบนชุด V1 |
| ตัวแทนของ run | champion ของ snapshot ที่ V1 สูงสุด (ภายในงบหรือภายในช่วงอิ่มตัวตามที่ระบุ) |
| D × w | ชั้นซ่อน D ชั้น ชั้นละ w โหนด, D = 0 คือ Linear |
| d | มิติ input = จำนวนค่าการรับรู้ (S หรือ k) + 4 |
| P | จำนวนพารามิเตอร์ของโครงข่าย = (d+1)w + (D−1)(w+1)w + (w+1)·4, และ D = 0: (d+1)·4 |
| P_pre | พารามิเตอร์ของการเตรียม input (ค่าเฉลี่ย/SD สำหรับ standardize และเมทริกซ์ PCA) นับรวมในขนาดโมเดลของขั้น 4 |

### 4.5 GA (แบบเดียวกันทุกความลึก)
อิง Deep GA (Such et al., 2017): **ไม่มี crossover ไม่มี immigrant** เพื่อไม่ให้ตัวอัลกอริทึมเปลี่ยนตามจำนวนชั้น

## 5. การประเมินผลและสถิติ

### 5.1 ตัวชี้วัด
- **race score ต่อสนาม:** s = 100 · (ความคืบหน้า/ความยาว) + [จบรอบ ? 100 · v_avg / v_ref : 0] โดย v_ref = ความเร็วเฉลี่ยของตัวควบคุมอ้างอิงบนสนามนั้น
  - การจบรอบชนะการไม่จบเสมอ (≥ 100 เทียบกับ < 100)
  - ไม่มีเพดาน รถที่จบทุกสนามยังแยกกันด้วยความเร็วได้
- **คะแนนของ config:** ค่าเฉลี่ยของ s บนชุดสนามที่ระบุ
- **ตัวชี้วัดรอง:**
  - อัตราจบรอบ
  - **เวลาต่อรอบแบบจับคู่** (เทียบเฉพาะสนามที่ทั้งสอง config จบรอบ เพื่อเลี่ยง survivorship bias)
  - **กราฟ survival (Kaplan–Meier)** ของระยะทางจนชน (censor ที่เส้นชัย)
  - ความยากสูงสุดที่ถึง
- **ความเร็วในการเรียน:**
  - AULC = ค่าเฉลี่ยคะแนน V1 ที่จุดวัด 25, 50, …, H รุ่น ด้วย **horizon H คงที่เท่ากันทุก run** (H = G ของขั้นนั้น)
  - จำนวนรุ่นจนถึงความยาก 1.0

### 5.2 สถิติ
- ทุก config ใช้ **5 seed**
- ความไม่แน่นอนใช้ **hierarchical bootstrap** (สุ่มซ้ำ seed แล้วสุ่มซ้ำสนามภายใน) 10,000 รอบ รายงาน mean และ 95% CI รวมความแปรปรวนทั้งจาก seed และจากการสุ่มสนาม
- **การเทียบที่กำหนดล่วงหน้า (confirmatory):** ระบุในแต่ละขั้น ใช้ Holm correction ภายในขั้น การเทียบอื่นทั้งหมดถือเป็นการสำรวจ (exploratory) และรายงานแยก
- **ความเทียบเท่า:** TOST ด้วย margin δ = 5 คะแนน race score
- **ไม่เพิ่ม seed หลังเห็นผล** (ไม่มี optional stopping) ถ้าผลสรุปไม่ได้ ให้รายงานว่าสรุปไม่ได้

### 5.3 กฎเลือก config ที่ส่งต่อ (ใช้ V2 เท่านั้น)
1. หา config ที่คะแนน V2 เฉลี่ยสูงสุด (B)
2. config X ถือว่า "เทียบเท่า B" ถ้า TOST ยืนยันว่า |X − B| < δ (α = 0.05)
3. ในกลุ่มที่เทียบเท่า เลือก d น้อยที่สุด ถ้าไม่มีตัวใดผ่าน TOST เลือก B
4. ใช้ใน 3 ขั้นถัดไป และรายงานคะแนน T ของทุก config เพื่อให้เห็นว่าการเลือกไม่ได้เอียง

### 5.4 กฎอิ่มตัว (ขั้น 3)
- เริ่มนับ **หลังความยากถึง 1.0 เท่านั้น**
- อิ่มตัวเมื่อ race score บน V1 ของ champion ไม่ดีขึ้นเกิน ε = 1.0 คะแนน จากค่าสูงสุดที่เคยได้ ติดกัน 8 จุดวัด (200 รุ่น)
- เพดาน 3,000 รุ่น † run ที่ชนเพดานถูกบันทึกว่า **censored** และรายงานแยก

### 6.1 ขั้น 1: เซนเซอร์ดิบ (RQ1)

- **ตัวแปรต้น:** S ∈ {3, 5, 9, 17} (2ⁿ+1, รังสีซ้อนกัน 3 ⊂ 5 ⊂ 9 ⊂ 17 มีรังสีตรงหน้าเสมอ) มุมมองรวม 200°
- **สองแขน** เพื่อแยกผลของ "ข้อมูล" ออกจาก "การจัดสรรความจุ":

| config | S | d | แขน a: param-matched | P | แขน b: ความกว้างคงที่ | P |
|---|---|---|---|---|---|---|
| S3 | 3 | 7 | 2×21 | 718 | 2×16 | 468 |
| S5 | 5 | 9 | 2×20 | 704 | 2×16 | 500 |
| S9 | 9 | 13 | 2×18 | 670 | 2×16 | 564 |
| S17 | 17 | 21 | 2×16 | 692 | 2×16 | 692 |

  แขน a ล็อกจำนวนพารามิเตอร์ (ขนาดปริภูมิค้นหาเท่ากัน) แต่สัดส่วนความจุระหว่างชั้นเปลี่ยน ส่วนแขน b ล็อกรูปทรงชั้นซ่อน แต่ P เปลี่ยน ถ้าทั้งสองแขนให้แนวโน้มเดียวกัน ข้อสรุปเรื่องข้อมูลจึงเชื่อถือได้ ถ้าต่างกัน ความต่างนั้นคือผลของการจัดสรรความจุ
- **งบ:** G รุ่น, 7 config (S17 ใช้ร่วมกันสองแขน) × 5 seed = 35 run
- **การเทียบที่กำหนดล่วงหน้า:** ผลต่างเพื่อนบ้าน S3↔S5, S5↔S9, S9↔S17 ในแขน a และค่า diminishing-returns Δ(5→9) − Δ(9→17)
- **ผลที่คาดหวัง:**
  - S3 ด้อยชัด: รังสีเฉียงห่างแนวหน้า 100° มองไม่เห็นทิศของโค้งถัดไปทันเวลา จะชนที่ hairpin และโค้งต่อเนื่อง
  - คะแนนเพิ่ม 3 → 5 → 9 แล้วชะลอที่ 9 → 17 (Δ(5→9) − Δ(9→17) > 0)
  - แขน b: S17 อาจเรียนช้ากว่าเล็กน้อยใน AULC เพราะมีพารามิเตอร์มากที่สุด แต่เพดานที่รุ่น G ไม่ต่ำกว่า S9
  - การ encode แบบ log + standardize ทำให้สัญญาณตำแหน่งด้านข้างมีขนาดใกล้เคียงกันทุก S (แก้ artifact ของ v1) ความต่างที่เหลือจึงมาจากความละเอียดเชิงมุมจริง

### 6.2 ขั้น 2: PCA (RQ2), รันขนานกับขั้น 1

| config | การเตรียม input | d | โครงข่าย (param-matched) | P | P_pre |
|---|---|---|---|---|---|

  - **PCA กับการฉายสุ่ม:** K4↔R4, K8↔R8 ตอบว่าการเรียงตาม eigenvalue มีประโยชน์จริงหรือแค่การลดมิติก็พอ
  - **การหมุนแกน:** K17↔S17 ตอบว่าการหมุนแกน (ไม่ลดมิติ) ช่วย GA หรือไม่ ถ้าไม่ต่าง แปลว่าผลของ PCA มาจากการลดมิติ ไม่ใช่จากฐานใหม่
- **การวิเคราะห์เชิงพีชคณิตเชิงเส้น (ไม่ต้องเทรน):**
  - scree plot และร้อยละความแปรปรวนสะสม
  - eigenvector 4 ตัวแรกวาดเป็นรูปพัดเซนเซอร์
  - **ความสัมพันธ์ของแต่ละ PC กับคำสั่งพวงมาลัยและเบรกของตัวควบคุมอ้างอิงบนชุด C** เพื่อตรวจว่า PC ที่ variance ต่ำสำคัญต่อการควบคุมหรือไม่ (ข้อเตือนของ Jolliffe, 1982)
- **ผลที่คาดหวัง:**

  - PC1 ≈ "ข้างหน้าโล่งแค่ไหน", PC2 ≈ "ซ้ายต่างขวา", PC3 ≈ "ตรงกลางต่างด้านข้าง"
  - K4/K8 ≥ S5/S9 (ข้อมูลจาก 17 เส้นถูกสรุปไว้)
  - K ≥ R ที่ k เดียวกัน
  - K17 ≈ S17
  - K2 ด้อยเพราะสัญญาณด้านข้างอยู่ใน PC ลำดับหลัง ซึ่งตรวจได้จากความสัมพันธ์ในข้อวิเคราะห์ข้างบน

**การเลือก I\*:** ใช้กฎข้อ 5.3 กับทุก config ของแขน a ขั้น 1 และทุก config ของขั้น 2 รวมกัน

### 6.3 ขั้น 3: ขนาดสมอง (RQ3)

- **ตัวแปรต้น:** D ∈ {1, 2, 3} × w ∈ {4, 8, 16, 32} + Linear = 13 โครงสร้าง (ทุกชั้นซ่อนกว้างเท่ากัน)
- **input:** I\*
- **จำนวนพารามิเตอร์** (ตัวอย่างเมื่อ d = 12):

| D \ w | 4 | 8 | 16 | 32 |
|---|---|---|---|---|
| 0 | 52 | | | |
| 1 | 72 | 140 | 276 | 548 |
| 2 | 92 | 212 | 548 | 1,604 |
| 3 | 112 | 284 | 820 | 2,660 |

- **การเทรน:** จนอิ่มตัวตามข้อ 5.4, snapshot ทุก 25 รุ่น, 13 × 5 seed = 65 run
  - **แบบงบเท่ากัน:** ตัวแทนเลือกจาก snapshot ≤ G
  - **แบบอิ่มตัว:** ตัวแทนเลือกจากทุก snapshot
- **การเทียบที่กำหนดล่วงหน้า (Holm ภายในชุด):**
  1. ลึกเทียบกว้างที่ P เท่ากันพอดี: 1×32 ↔ 2×16 (P = 548 เมื่อ d = 12 และเท่ากันทุก d)
  2. Linear ↔ 1×4 (ประโยชน์ขั้นต่ำของความไม่เชิงเส้น)
  3. ความกว้างที่ D = 2: 2×8 ↔ 2×16 ↔ 2×32
  4. งบเท่ากันเทียบอิ่มตัว: อันดับของโครงสร้างเปลี่ยนหรือไม่ (Kendall τ)
- **การรายงานความเร็ว:** กราฟคะแนนเทียบรุ่น และเทียบเวลาจำลองสะสม (simulated seconds) เพราะ "รุ่น" ของ run ที่ขับนานกว่าใช้การคำนวณมากกว่า รวมถึงกราฟความยากเทียบรุ่น
- **SVD (เชิงพีชคณิตเชิงเส้น):**
  - singular value ของทุกชั้นของตัวแทนอิ่มตัว ชั้นแรกใช้ W·Σx^{1/2} (Σx = covariance ของ input บนชุด C)
  - effective rank สองแบบ: พลังงาน 90% และแบบ entropy (Roy & Vetterli, 2007) หารด้วย min(m, n)
  - **baseline สำหรับเทียบ:** น้ำหนักตอน init และเมทริกซ์สุ่มที่ Frobenius norm เท่ากัน เพราะการกลายพันธุ์แบบ Gaussian สะสม noise ที่ทำให้ rank ดูเต็ม
- **ผลที่คาดหวัง:**
  - **งบเท่ากัน:** 2×8 และ 2×16 ดีที่สุด, w = 32 และ D = 3 ช้ากว่า (การกลายพันธุ์สเกลตาม fan-in แล้ว ที่เหลือคือผลของมิติการค้นหาที่สูงขึ้นต่อ GA)
  - **อิ่มตัว:** ช่องว่างแคบลง w = 4 มีเพดานต่ำชัด
  - **Linear:** ขับจบ T-easy ที่ความยาก 0.5 ได้บางส่วน แต่จบ T ที่ความยาก 1.0 น้อยกว่า 50% เพราะการตัดสินใจเบรกก่อนโค้งขึ้นกับผลคูณระหว่างความเร็วกับระยะ ซึ่งเป็นฟังก์ชันไม่เชิงเส้น
  - **1×32 ↔ 2×16:** ลึกได้เปรียบเล็กน้อย
  - **SVD:** effective rank ของชั้นกว้าง (w = 32) ต่ำกว่า baseline สุ่มอย่างมีนัยสำคัญ

### 6.4 ขั้น 4: การบีบอัด (RQ4, RQ5, RQ6)

#### 6.4.1 หน่วยวัด
- **ขนาด (บิต)** = บิตของน้ำหนัก + บิตของไบแอส + บิตของค่าสเกล + P_pre × 32
- **compression ratio** = ขนาดของโมเดลต้นทาง (float32) / ขนาดหลังบีบ
- **แกนหลักของทุกการเปรียบเทียบคือ compression ratio** ไม่ใช่ "ระดับ" เพราะระดับเดียวกันให้ ratio ต่างกันตามความลึก
- เปรียบเทียบที่ ratio เป้าหมาย {2, 4, 8, 16}: แต่ละวิธีใช้ค่าตั้งที่ได้ ratio ≥ เป้าใกล้ที่สุด และถ้ามีหลายค่าตั้งให้เลือกด้วย V2

#### 6.4.2 วิธีการ

| รหัส | วิธี | รายละเอียด |
|---|---|---|
| PR-A | ตัดโหนดตามความสำคัญ | ความสำคัญของโหนด j = ‖W_next[:, j]‖ · std(a_j) จากชุด C, ชดเชย b_next += W_next[:, ตัด] · mean(a_ตัด) |
| PR-LS | ตัดโหนด + แก้ชั้นถัดไปด้วย least squares | เลือกโหนดแบบ PR-A แล้วหา W' ที่ทำให้ ‖W_next·A − W'·A_เหลือ − c‖² ต่ำสุดบนชุด C (สมการปกติ + ridge λ = 10⁻³) เป็นการประมาณเชิงเส้นที่ดีที่สุดของชั้นถัดไป (แนว ThiNet; Luo et al., 2017) |
| PR-R | ตัดสุ่ม (กลุ่มควบคุม) | ชดเชยแบบ PR-A เฉลี่ย 5 ครั้ง |
| Q | Quantization | สเกลต่อ output (ต่อแถวของ W), แบบสมมาตร 2^(b−1)−1 ระดับ, clipping ratio เลือกจาก grid {1.0, 0.9, …, 0.5} ให้ MSE ต่ำสุด, ไบแอสเก็บ 16 บิตแยกสเกล, b ∈ {2, …, 16} |
| SVD (เสริม) | low-rank ต่อชั้น | W ≈ U_r Σ_r V_rᵀ, ขนาด r(m + n) ค่า |
| MIX | PR-LS แล้ว Q | ทุกคู่ (ความกว้าง, บิต) ที่ได้ ratio ตามเป้า เลือกด้วย V2 |

- **รูปแบบการตัด:** ตัดความกว้างลงทีละครึ่ง (32 → 16 → 8 → 4) ทำให้รูปทรงตรงกับโมเดลเล็กในกริดพอดี และไม่ตัดจน w < 2
- **แต่ละวิธีมีสองโหมด:**
  - **ไม่ fine-tune:** บีบแล้วประเมินทันที
  - **fine-tune:** บีบแล้วเทรน GA ต่อ 50 รุ่นที่ความยาก 1.0 ด้วย σ_rel = 0.02 ใช้ protocol เดียวกันทุกวิธี (Blalock et al., 2020) สำหรับ Q จะกลายพันธุ์ค่า float แล้ว quantize ใหม่ทุกครั้งที่ประเมิน
- **วินิจฉัยเพิ่ม:** open-loop action error (RMSE ของ output เทียบกับโมเดลต้นทางบนสถานะจากชุด C) รายงานคู่กับคะแนน closed-loop เพื่อแยก "ความคลาดเคลื่อนต่อก้าว" ออกจาก "ความคลาดเคลื่อนที่สะสมเมื่อรถไปเจอสถานะใหม่"

#### 6.4.3 RQ4: ที่ ratio เท่ากัน วิธีไหนดีที่สุด
- **ต้นทาง:** ตัวแทนอิ่มตัวของ D×32 ทุก D และ 2×16 × 5 seed
- **กราฟ:** คะแนน T เทียบ ratio (แกน log) แยกเส้นต่อวิธี และแยกแผงไม่ fine-tune / fine-tune
- **เทียบที่กำหนดล่วงหน้า:** ที่ ratio 4 และ 8: PR-A ↔ PR-R (เกณฑ์ความสำคัญมีความหมายไหม), PR-LS ↔ PR-A (least squares ช่วยไหม), Q ↔ PR-LS
- **ข้อเท็จจริงเชิงโครงสร้าง:** Q ไปได้สูงสุดราว 16 เท่า (32 → 2 บิต) ขณะที่การตัดความกว้างลดพารามิเตอร์ตามกำลังสองของ w สอง ratio ที่สูงที่สุดจึงเทียบได้แค่ PR, SVD และ MIX รายงานจุดที่วิธีใดทำไม่ได้ว่า "N/A" ไม่นับเป็นคะแนนศูนย์
- **ผลที่คาดหวัง:**
  - ไม่ fine-tune: Q ดีที่สุดที่ ratio 2–4, PR-LS > PR-A > PR-R, D = 3 ไวต่อ Q มากกว่าเมื่อเทียบที่ ratio เท่ากัน
  - fine-tune: ช่องว่างระหว่าง PR กับ Q แคบลงมาก
  - ratio ≥ 8: MIX ดีที่สุด

#### 6.4.4 RQ5: ใหญ่บีบเทียบกับเล็กที่เทรนเอง
- **คู่เปรียบเทียบ** (รูปทรงเดียวกัน หรือขนาดบิตเท่ากัน) แบบจับคู่ seed:

| ต้นทาง → เป้า | PR-LS | Q (บิตให้ขนาดไม่เกินเป้า) | เทียบกับ |
|---|---|---|---|
| D×32 → ขนาด D×16 | ตัดเป็น D×16 | b = ⌊32 P₁₆/P₃₂⌋ | D×16 ที่เทรนจนอิ่มตัว |
| D×32 → ขนาด D×8 | ตัดเป็น D×8 | b = ⌊32 P₈/P₃₂⌋ (ถ้า < 2 → N/A ใช้ MIX) | D×8 ที่เทรนจนอิ่มตัว |
| D×16 → ขนาด D×8 | ตัดเป็น D×8 | b = ⌊32 P₈/P₁₆⌋ | D×8 ที่เทรนจนอิ่มตัว |

- **สมมติฐานที่แข่งกัน (กำหนดล่วงหน้า):**
  - **H5a (บีบชนะ):** GA ในมิติสูงไปถึงนโยบายที่ดีกว่า และความรู้อยู่ใน subspace ต่ำ ที่ PR-LS เก็บไว้ได้ด้วย least squares
  - **H5b (เล็กชนะ):** ข้อดีของ "เทรนใหญ่แล้วบีบ" ในงาน gradient descent (Li et al., 2020; Frankle & Carbin, 2019) มาจาก overparameterization ที่ช่วย gradient แต่ GA ได้ประโยชน์น้อยหรือเสียจากมิติที่สูงขึ้น
  - ถ้าโมเดลใหญ่อิ่มตัวมีคะแนนไม่สูงกว่าโมเดลเล็ก (ขั้น 3) H5a เป็นไปไม่ได้ตั้งแต่ต้น ในกรณีนั้นจะรายงานว่า RQ5 ถูกตอบด้วยผลขั้น 3 แล้ว
- **คาดการณ์:**
  - ไม่ fine-tune: เป้า ratio ~2–3 Q ใหญ่ ≈ เล็กเทรนเอง แต่ที่ ratio ≥ 6 เล็กเทรนเองชนะ
  - fine-tune: ใหญ่บีบสูสีหรือชนะที่ ratio ต่ำ

#### 6.4.5 Pareto รวม
- **จุดบนกราฟ:**
  - ตัวแทนอิ่มตัวทุกโครงสร้างในกริด
  - ผลบีบอัดทุกวิธี ทุก ratio ทั้งสองโหมด
- **เลือกค่าตั้งบน V2 แล้วรายงาน T**
- **กราฟ:** คะแนน T เทียบขนาดบิต (log) พร้อมเส้น Pareto ต่อกลุ่ม
- **ข้อเตือน:** การเลือกจุดสูงสุดจาก variant จำนวนมากมีความลำเอียงทางบวก จึงต้องใช้ V2 เลือกเท่านั้น

#### 6.4.6 RQ6: ระยะเวลาเทรนกับความทนต่อการบีบ
- **ข้อมูล:** snapshot ของ 2×32 และ 2×16 ทุก 100 รุ่น (หลังถึงความยาก 1.0) × 5 seed
- **ความทนต่อการบีบ:** การเสียคะแนน = คะแนนฐาน − คะแนนหลังบีบ (PR-LS เหลือครึ่ง และ Q 4 บิต แบบไม่ fine-tune)
- **ตัวแปรกลไก (วัดทุก snapshot):**
  - norm ของน้ำหนักต่อชั้น
  - สัดส่วนโหนดที่อิ่มตัว (|a| > 0.95 บนชุด C)
  - **flatness** คือคะแนนเมื่อรบกวนน้ำหนักแบบ Gaussian σ_rel ∈ {0.01, 0.03, 0.1}
- **ควบคุมตัวกวน:**
  - จับคู่ snapshot ที่คะแนนฐานใกล้กัน (ต่างกันไม่เกิน 5) เพื่อตัด floor effect
  - วิเคราะห์ด้วย hierarchical bootstrap ที่ resample ตาม run เพราะ snapshot ใน run เดียวกันไม่อิสระต่อกัน
- **สมมติฐานที่แข่งกัน:**
  - (ก) การคัดเลือกค่อย ๆ หาบริเวณที่ราบของ fitness landscape → flatness เพิ่ม และทนการบีบเพิ่ม
  - (ข) น้ำหนักโตขึ้นจากการกลายพันธุ์สะสม → tanh อิ่มตัวมากขึ้น ทำงานคล้าย threshold จึงทนต่อ Q แต่ไม่ช่วยด้าน PR
  - (ค) ไม่มีความสัมพันธ์
  - แยกได้ด้วยรูปแบบของตัวแปรกลไก และความต่างระหว่าง Q กับ PR

## 8. ข้อจำกัดที่ยอมรับ (ระบุในรายงาน)

1. **สนาม:** procedural ยาว 1.5–1.8 km สั้นกว่าสนาม F1 จริง จึงเรียกว่า "F1-like (ย่อส่วน)" การทดสอบ OOD ด้วยเลย์เอาต์สนามจริง (TUMFTM racetrack-database) เป็นงานเสริม ไม่ใช่ข้อสรุปหลัก
2. **ฟิสิกส์:** 3 DOF ไม่มี roll/pitch/load transfer ด้านข้าง ไม่มีแบบจำลองยางสึกและความร้อน, มี noise เซนเซอร์ แต่ไม่มี latency
3. **Optimizer:** ข้อสรุป RQ3 และ RQ5 ผูกกับ GA ที่ใช้ (สเกลการกลายพันธุ์ตาม fan-in ลดผลกวนแล้วแต่ไม่หมด) ไม่ได้ตรวจซ้ำด้วย CMA-ES หรือ OpenAI-ES เพราะเกินขอบเขต
4. **สถิติ:** 5 seed ยังให้ power จำกัดกับผลขนาดเล็ก รายงานเป็น CI เสมอ และระบุชัดเมื่อสรุปไม่ได้
5. **การบีบอัด:** quantization ลดขนาดการเก็บ ไม่ได้วัด latency หรือ compute จริง
